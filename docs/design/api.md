# API 总体设计

## 概述

API 基础设计定义 prompts-glue 各服务接口共同遵循的访问、认证、响应、分页和安全约定。具体业务 API 文档只描述业务资源、接口路径和字段含义，不重复定义通用规则。

## 设计目标

- 统一 CLI、Web、Manager 与后端服务之间的 API 交互格式。
- 保证响应结构稳定，便于命令行展示、前端渲染和自动化处理。
- 统一认证、错误、分页和时间格式，减少模块间重复设计。
- 为 Registry API 和后续业务 API 提供共同基础。

## 基础约定

| 项目　　 | 说明　　　　　　　　　　　　　 |
| ----------| --------------------------------|
| 数据格式 | 请求和响应使用 JSON　　　　　　|
| 字符编码 | UTF-8　　　　　　　　　　　　　|
| 时间格式 | UTC 时间　　　　　　　　　　　 |
| 内容传输 | 文本内容与结构化元数据分离传输 |
| 请求追踪 | 每个响应都应包含请求追踪标识　 |

业务 API 按资源职责划分前缀。

| API 分组 | 前缀 | 说明 |
|---|---|---|
| Registry API | `/api/registry` | 提示词包注册、搜索、下载、发布、依赖解析和实时生成 |
| 字典 API | `/api/dicts` | 前端和客户端加载统一业务字典 |
| 管理 API | `/api/admin` | 管理端用户、命名空间、配置、风险、审计、缓存等运营能力 |

## 认证方式

需要用户身份的接口应携带访问凭据。公开资源可允许匿名访问，私有资源、发布操作、管理操作必须认证。

| 场景 | 认证要求 |
|---|---|
| 访问公开资源 | 可匿名访问 |
| 访问私有资源 | 必须认证且具备访问权限 |
| 创建或发布资源 | 必须认证且具备维护权限 |
| 修改或废弃资源 | 必须认证且具备维护权限 |
| 管理操作 | 必须认证且具备管理权限 |

认证凭据不得出现在 URL 查询参数、日志、业务内容、缓存内容或错误详情中。

## 响应结构

所有 API 响应应使用统一结构。

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| success | 布尔值 | 是 | 请求是否成功 |
| data | 任意 | 否 | 成功时的业务数据 |
| error | 错误对象 | 否 | 失败时的错误信息 |
| request_id | 字符串 | 是 | 请求追踪标识 |

成功响应应设置 `success` 为真，并在 `data` 中返回业务数据。失败响应应设置 `success` 为假，并在 `error` 中返回错误信息。

## 错误对象

错误对象结构如下：

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| code | 字符串 | 是 | 错误码，具体取值由业务 API 在 dicts.md 中定义 |
| message | 字符串 | 是 | 面向用户的错误说明 |
| details | 映射 | 否 | 字段错误、依赖错误、权限错误等补充信息 |

错误信息应便于用户定位问题，但不得暴露密钥、令牌、内部调用栈或其他敏感信息。

## 分页结构

列表接口统一使用分页结构。

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| items | 列表 | 是 | 当前页数据 |
| page | 数值 | 是 | 当前页码 |
| page_size | 数值 | 是 | 每页数量 |
| total | 数值 | 是 | 总数量 |
| has_more | 布尔值 | 是 | 是否还有更多数据 |

分页接口应限制最大 `page_size`，避免单次请求返回过多数据。

## 字典 API

字典 API 为 Web、Manager 和 CLI 提供统一编码来源。前端所有业务编码均应通过字典 API 加载，不在前端代码中硬编码。

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/dicts` | 获取所有启用字典分组和字典项 |
| GET | `/api/dicts/{group}` | 获取指定分组的启用字典项 |

字典项结构如下：

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| group | 字符串 | 是 | 字典分组 |
| value | 字符串 | 是 | 字典值 |
| label | 字符串 | 是 | 展示名称 |
| description | 字符串 | 否 | 说明 |
| sort_order | 数值 | 是 | 排序 |
| enabled | 布尔值 | 是 | 是否启用 |
| system | 布尔值 | 是 | 是否系统内置 |

## 管理 API

管理 API 面向 Manager，所有接口都需要认证和相应管理权限。

| 资源 | 能力 |
|---|---|
| 用户 | 查询用户、调整状态、查看登录和令牌摘要 |
| 命名空间 | 查询命名空间、成员和角色，维护成员关系 |
| 包与版本 | 运营查询、废弃版本、查看下载和事件 |
| 字典 | 创建、更新、启用、禁用和排序字典项 |
| 服务配置 | 查询和更新服务级配置，敏感配置不回显明文 |
| 风险标记 | 创建、查询、处理和关闭风险标记 |
| 审计日志 | 按用户、资源、动作和时间查询审计记录 |
| 生成记录 | 查询实时生成和复合提示词计算记录 |
| 缓存 | 查询缓存统计和清理缓存项 |

## 安全要求

- 认证凭据、密钥和令牌不得写入业务内容、日志、缓存和错误详情。
- 写操作应校验身份、权限和资源归属。
- 请求体大小、调用频率和列表分页大小应有上限。
- 对外返回的错误信息应避免泄露内部实现细节。
- API 应支持请求追踪，便于审计和问题定位。
